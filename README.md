# AHM X Video Downloader Bot 🔴⚫

بوت تيليجرام لتنزيل فيديوهات عامة من المواقع التي يدعمها `yt-dlp`، مع عرض العنوان والناشر والمدة والصورة المصغّرة، واختيار الدقة، والحجم التقريبي، أو تحويل الصوت إلى MP3.

> **الاستخدام المسؤول:** نزّل فقط المحتوى الذي تملكه أو تملك إذنًا بتنزيله. المشروع لا يتجاوز DRM أو تسجيل الدخول أو إعدادات الوصول، ولا يدعم الفيديوهات الخاصة. تحقّق من شروط المنصة وحقوق النشر قبل الاستخدام.

## المزايا

- استقبال رابط فيديو في محادثة خاصة مع البوت.
- عرض العنوان والناشر والمدة والمشاهدات عند توفرها والصورة المصغّرة.
- أزرار اختيار جودة من الجودات المتاحة حتى 1080p افتراضيًا.
- عرض تقدير لحجم كل اختيار، مع توضيح عندما لا يكون الحجم معروفًا.
- استخراج الصوت إلى MP3.
- شريط تقدم مبسط أثناء التحميل عندما يوفّر الموقع بيانات تقدم.
- إرسال الفيديو/الصوت للمستخدم ثم حذف ملفات العمل المؤقتة.
- Webhook مناسب لخدمة Render Web Service، مع endpoint لفحص الصحة.
- فحص للرابط لمنع العناوين المحلية والشبكات الخاصة الشائعة.

## متطلبات مهمة

- حد الرفع الافتراضي داخل البوت 49 MB لتفادي الحد السحابي الشائع لواجهة Telegram Bot API. يمكن تعديله بمتغير `MAX_UPLOAD_MB`، لكن رفع حد التطبيق لا يغيّر حدود تيليجرام نفسها.
- أرقام الحجم المعروضة تقديرية؛ الحجم النهائي يتوقف على صيغة المصدر وطريقة دمج الصوت والفيديو.
- `yt-dlp` يدعم مواقع كثيرة وليس كل المواقع مضمونة. بعض المواقع تغيّر أنظمتها وقد يتعطل الاستخراج مؤقتًا.
- قد ترفض بعض روابط YouTube أو غيرها بسبب القيود التي يفرضها الموقع. هذا البوت لا يضيف ملفات cookies أو بيانات دخول لتجاوز تلك القيود.
- Render Free يستخدم نظام ملفات مؤقتًا وقد يوقف الخدمة عند الخمول؛ لذلك لا يحتفظ المشروع بالتنزيلات بعد العملية. يمكن أن تتأخر أول استجابة بعد فترة خمول.

## تشغيل محلي للاختبار

1. أنشئ بوت من `@BotFather` وخذ التوكن.
2. ثبّت Docker، ثم شغّل المشروع عبر Docker. يلزم رابط HTTPS عام حتى يستقبل Telegram الـ webhook؛ الاختبار المحلي المباشر يتطلب نفق HTTPS موثوقًا.
3. عرّف المتغيرات:
   - `TELEGRAM_BOT_TOKEN` — توكن البوت.
   - `WEBHOOK_SECRET` — سر عشوائي يحتوي على حروف إنجليزية وأرقام و`_` أو `-`.
   - `WEBHOOK_URL` — الرابط العام HTTPS لخدمتك. على Render تُستخدم `RENDER_EXTERNAL_URL` تلقائيًا.
4. ارفع المشروع إلى GitHub، ثم اربط المستودع في Render كخدمة Web Service تستخدم Docker.

## النشر على Render

1. ارفع الملفات إلى مستودع GitHub.
2. في Render اختر **New + → Blueprint** وحدد المستودع الذي يحتوي `render.yaml`، أو أنشئ Web Service باستخدام Docker.
3. أضف متغير البيئة `TELEGRAM_BOT_TOKEN` من لوحة Render. لا تضع التوكن داخل الكود أو GitHub.
4. انشر الخدمة وانتظر أن يصبح `/health` بحالة `ok`.
5. افتح البوت واضغط Start ثم أرسل رابطًا عامًا مدعومًا.

Render يوفر `RENDER_EXTERNAL_URL` لخدماته العامة؛ لذلك لا تحتاج إلى إدخال `WEBHOOK_URL` يدويًا عند استخدام Render. وفي حال الاستضافة في مكان آخر، عرّف `WEBHOOK_URL` بعنوان HTTPS العام.

## إعدادات اختيارية

| المتغير | الافتراضي | الوظيفة |
|---|---:|---|
| `MAX_UPLOAD_MB` | `49` | الحد المحلي لحجم الملف المرسل بالـ MB |
| `MAX_VIDEO_HEIGHT` | `1080` | أعلى ارتفاع فيديو يعرضه البوت |
| `MAX_ACTIVE_DOWNLOADS` | `2` | أقصى عمليات تنزيل متزامنة إجمالًا |
| `PORT` | `10000` | المنفذ الذي يستمع إليه التطبيق |
| `LOG_LEVEL` | `INFO` | مستوى السجل |

## استكشاف أخطاء سريعة

- **`TELEGRAM_BOT_TOKEN` missing:** أضف التوكن في Environment على Render ثم أعد النشر.
- **الخدمة لا تسجّل webhook:** تأكد أن الخدمة عامة وتعمل بـ HTTPS، وأن `RENDER_EXTERNAL_URL` متاح.
- **فشل استخراج رابط:** تحقق من أن الفيديو عام، ومن تحديث `yt-dlp` في Build جديد، ومن أن الموقع ما زال مدعومًا.
- **الملف أكبر من الحد:** اختر دقة أقل. خفض `MAX_UPLOAD_MB` أو رفعه لا يلغي حد تيليجرام أو قيود المنصة.
- **الموقع طلب تسجيل الدخول أو منع التنزيل:** لا تستخدم البوت لتجاوز ذلك؛ جرّب رابطًا عامًا مصرحًا بتنزيله.
